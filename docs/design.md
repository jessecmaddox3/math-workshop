# How Math Workshop is designed

> **TL;DR:** Preserve the full original pair of games: exact arithmetic and visible expression building in Target Number, deliberately unscaled reasoning puzzles in Area Mazes. Save locally first; optional cloud never defines a learner by name.

Target Number fuses selected chips rather than asking a player to type brackets. Every result keeps its expression, with parentheses around earlier work, and a separate step list shows the arithmetic. This lets the player work on decomposition and strategy while the app handles notation. Selection order matters for subtraction and division. Division by zero changes neither chips nor history.

The solver explores pairwise expressions using reduced rational values. It returns at most one representative solution for a reachable value, not every distinct expression. Generated cards are checked before play, with a known-solvable fallback. A structural hint describes a route from the original numbers, explicitly asking the player to undo or start over when needed. It does not falsely claim to solve the remaining chips after an arbitrary partial attempt.

A completed wrong result counts as an attempt and resets the per-target streak and current mastery. Two credited successful routes in a row establish per-target mastery. Exact repeated successful expressions on the current card do not add attempts or success credit; different expression strings count as different routes, even when algebraically equivalent. The first solution on each new card contributes to solved-card and tier progression. Additional routes increment a separate counter. Unfinished resets/skips are neutral. Automatic next-card timing is optional; no countdown or speed bonus limits solving time.

Area Mazes has 17 original puzzles in three tiers (5, 6, 6). All displayed givens are sufficient, all requested answers are positive integers, and shared dimensions are consistent. Tier 3 encourages ratios without claiming division is impossible. The screen geometry deliberately varies independently of the true dimensions, and accessible text repeats only the visible givens. Blank/nonfinite input is not an attempted answer. A successful puzzle is marked mastered; a later wrong answer resets its streak without erasing the historical success. The game keeps per-puzzle counters and a set of completed puzzles, and cycles through a tier after its unsolved pool is exhausted.

Both controllers keep transient chips, selections, puzzle IDs and timers out of persisted progress. Learner changes, imports and accepted cloud snapshots reload the controller’s state in place and cancel old tasks. This works even when storage is unavailable. Saved snapshots have a game-specific curriculum ID and version; normalization bounds counters, validates tiers, and drops unknown puzzle keys. Future versions are rejected for recovery rather than silently reset.

## Local storage and optional cloud

The reusable save engine comes from this author’s MIT-licensed Colors release. Target and Area use separate IndexedDB databases, each with its own profiles, records and recovery copies. A revision check prevents competing tabs from blindly overwriting a save. A snapshot and its cloud outbox commit in one transaction. Failed/stale writes stop further answer changes and leave the current copy exportable. An unavailable database at startup instead gives a clearly labelled, usable temporary session.

Optional cloud uses the same reviewed adapter and schema, with game IDs `target` and `areamaze`. The host configuration and SDK load only after explicit adult opt-in. The pinned SDK uses page-memory authentication and no automatic login from stored tokens. RLS keys data by authenticated owner and random learner ID, with a composite foreign key preventing cross-owner attachment. A revision comparison and a unique write ID protect retries and detect edits from another device. Device/cloud choices preserve the other version as recovery; nicknames never merge records.

The panel distinguishes its own accepted attach/restore/conflict actions from passive outside changes. Accepted actions can update the current game in place without disconnecting before its upload. Passive changed revisions ask the user to export and reload. General improvements belong here; a private consumer can pin this release and keep actual learner exports and cloud configuration elsewhere.
